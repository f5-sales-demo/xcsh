Create and activate a named F5 Distributed Cloud context, then select a namespace.

<Aside type="caution" title="Confirm scope before mutation">A context selects credentials and an API endpoint. A namespace narrows the resource scope. Inspect both immediately before `create`, `apply`, `update`, or `delete`.</Aside>

## Prerequisites

- A current xcsh release and a shell in the intended working directory.
- Authorization for any account, tenant, repository, or file the procedure touches.
- A backup or dry run before an operation that changes or deletes state.

## Procedure

<Steps>

1. Start `xcsh` and run `/context create lab https://example.console.ves.volterra.io <token> example-namespace`.
2. Run `/context show lab` and `/context status`.
3. Change the active namespace with `/context namespace example-namespace`.
4. Run `xcsh get <kind> -n example-namespace` only after confirming the tenant and scope.

</Steps>

## Expected result

The command or interface reports completion in the selected scope. For automation, prefer its structured result instead of parsing decorated terminal output.

## Troubleshooting

Confirm the installed version and resolved configuration first. Retry with optional plugins, MCP servers, or extensions disabled when they could affect the path. Never print tokens while collecting diagnostics.
