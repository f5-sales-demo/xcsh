Choose one installation channel and keep using that channel for upgrades. Mixing a package-manager installation with a standalone binary makes version diagnosis ambiguous.

## How do I install on Ubuntu or Debian?

```bash
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://f5-sales-demo.github.io/apt-repo/f5xc-archive-keyring.gpg \
  | sudo tee /etc/apt/keyrings/f5xc-archive-keyring.gpg >/dev/null
echo "deb [arch=amd64,arm64 signed-by=/etc/apt/keyrings/f5xc-archive-keyring.gpg] https://f5-sales-demo.github.io/apt-repo stable main" \
  | sudo tee /etc/apt/sources.list.d/f5xc.list
sudo apt-get update
sudo apt-get install xcsh
```

macOS users can run `brew install f5-sales-demo/tap/xcsh`. Release binaries and archives are published on [GitHub Releases](https://github.com/f5-sales-demo/xcsh/releases).

## How do I confirm the selected executable?

```bash
command -v xcsh
xcsh --version
xcsh --help
```

The version must match the channel you selected. Upgrade with that package manager, or run `xcsh update --check` for an executable release installation.

## How do I remove it?

Use the inverse of the installation channel: `sudo apt-get remove xcsh`, `brew uninstall xcsh`, or remove the exact standalone path returned by `command -v`. User settings and sessions remain under the path reported by `xcsh config path`; remove them separately only if you no longer need them.
