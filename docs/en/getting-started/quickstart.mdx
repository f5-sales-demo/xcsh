Start an interactive session, inspect the available model, and validate a manifest without tenant credentials.

```yaml title="manifest.yaml"
kind: http_loadbalancer
metadata:
  name: example-load-balancer
  namespace: example-namespace
spec: {}
```

`xcsh validate` reads the packaged catalog and performs no tenant request. An empty `spec` may still fail the selected kind's minimum configuration; that failure proves local validation is working.

## Prerequisites

- A current xcsh release and a shell in the intended working directory.
- Authorization for any account, tenant, repository, or file the procedure touches.
- A backup or dry run before an operation that changes or deletes state.

## Procedure

<Steps>

1. Run `xcsh` in a project directory.
2. Enter `/model` to inspect or select a model.
3. Save the example manifest and run `xcsh validate -f manifest.yaml` in another terminal.
4. Review the validation report before configuring live access.

</Steps>

## Expected result

The command or interface reports completion in the selected scope. For automation, prefer its structured result instead of parsing decorated terminal output.

## Troubleshooting

Confirm the installed version and resolved configuration first. Retry with optional plugins, MCP servers, or extensions disabled when they could affect the path. Never print tokens while collecting diagnostics.
