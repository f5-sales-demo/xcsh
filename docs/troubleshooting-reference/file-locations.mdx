Locate user and project settings, sessions, contexts, plugins, agents, skills, tools, hooks, and memories.

| Scope | Primary locations |
| --- | --- |
| Project | `.xcsh/settings.json`, `.xcsh/mcp.json`, `.xcsh/contexts/`, `.xcsh/skills/`, `.xcsh/agents/`, `.xcsh/extensions/`, `.xcsh/tools/`, `.xcsh/hooks/`, `.xcsh/commands/`, `.xcsh/XCSH.md` |
| User | `~/.xcsh/agent/` for settings, sessions, memories, agents, and user integrations; `~/.xcsh/plugins/` for installed plugins |
| Override | `PI_CODING_AGENT_DIR` changes the primary user agent directory |

Compatibility discovery can read selected configurations from pi, Claude, Codex, Gemini, and other tools. Native xcsh paths take precedence; disable unused discovery providers when isolation matters.

## Prerequisites

- A current xcsh release and a shell in the intended working directory.
- Authorization for any account, tenant, repository, or file the procedure touches.
- A backup or dry run before an operation that changes or deletes state.

## Procedure

<Steps>

1. Use `xcsh config path` instead of assuming a platform path.
2. Look under `.xcsh/` for project-local configuration.
3. Look under `~/.xcsh/agent/` for primary user agent data.
4. Back up or remove files only after identifying their owner and sensitivity.

</Steps>

## Expected result

The command or interface reports completion in the selected scope. For automation, prefer its structured result instead of parsing decorated terminal output.

## Troubleshooting

Confirm the installed version and resolved configuration first. Retry with optional plugins, MCP servers, or extensions disabled when they could affect the path. Never print tokens while collecting diagnostics.
