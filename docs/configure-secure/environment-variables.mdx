Configure model providers, cloud routes, search tools, and xcsh runtime paths.

| Purpose | Variables |
| --- | --- |
| Core model APIs | `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `GITHUB_TOKEN` |
| Other model APIs | `AZURE_OPENAI_API_KEY`, `GROQ_API_KEY`, `CEREBRAS_API_KEY`, `XAI_API_KEY`, `OPENROUTER_API_KEY`, `KILO_API_KEY`, `MISTRAL_API_KEY`, `ZAI_API_KEY`, `MINIMAX_API_KEY`, `OPENCODE_API_KEY`, `CURSOR_ACCESS_TOKEN`, `AI_GATEWAY_API_KEY` |

## Prerequisites

- A current xcsh release and a shell in the intended working directory.
- Authorization for any account, tenant, repository, or file the procedure touches.
- A backup or dry run before an operation that changes or deletes state.

## Procedure

<Steps>

1. Set only variables required by the selected provider or tool.
2. Keep them in a protected shell or secret manager rather than `.env` files committed to Git.
3. Use the names printed by `xcsh --help` as the current authority.
4. Restart xcsh after changing its environment.

</Steps>

## Expected result

The command or interface reports completion in the selected scope. For automation, prefer its structured result instead of parsing decorated terminal output.

## Troubleshooting

Confirm the installed version and resolved configuration first. Retry with optional plugins, MCP servers, or extensions disabled when they could affect the path. Never print tokens while collecting diagnostics.
